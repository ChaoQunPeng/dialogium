# dialogium

成功的关键不在于"功能的有无"，而在于"价值的独特"。

市面上有众多工具，恰恰证明这是一个存在需求、已被验证的市场，而不是一个无人问津的伪需求。你的挑战不是从零创造市场，而是在现有市场中找到属于自己的位置。

制定计划任务清单时，最忌讳"既要又要"。对于第一个 MUD 游戏，你的目标应该是实现一个**"麻雀虽小，五脏俱全"的单机挂机版 MUD**。我为你整理了一份 MVP（最小可行性产品）开发计划清单。这份清单分为 5 个核心阶段：

## 第一阶段：核心战斗引擎（已完成 80%）

这是你目前正在做的，也是 MUD 的心脏。

- [x] 数值模拟：实现攻防血的扣减逻辑。
- [x] 文案系统：实现随机战斗描述。
- [x] 状态管理：处理战斗中、战斗结束的状态切换。
- [ ] 战后结算：实现经验值（修为）获取和等级（境界）提升。

## 第二阶段：基础养成与属性（让角色动起来）

在这个阶段，玩家需要一个"家"。

- [ ] 角色面板：展示姓名、境界、气血、攻击、防御。
- [ ] 境界体系：定义一套境界名（练气、筑基...）和升级所需的经验公式。
- [ ] 持久化存储：使用 localStorage 保存角色数据，保证刷新页面后进度不丢失。

## 第三阶段：物品与背包系统（获得感来源）

没有掉落的 MUD 只是纯文字阅读。

- [ ] 物品数据结构：定义 ID、名称、类型（消耗品/装备）、属性加成。
- [ ] 掉落逻辑：给怪物配置掉落表（权重随机）。
- [ ] 基础背包：实现物品的查看、使用（如加血药）和丢弃。
- [ ] 装备穿戴：实现武器/防具的加成效果（装备后攻击力增加）。

## 第四阶段：文字房间与地图（探索感来源）

MUD 不应该只有一个战斗界面，而应该有空间感。

- [ ] 房间模型：每个房间包含 id、名称、描述、出口列表（如：向东走、向北走）。
- [ ] 移动系统：玩家点击方位，切换当前所在的房间。
- [ ] 遇怪机制：某些房间是"野外"，进入后自动或手动触发战斗。

## 第五阶段：UI 交互优化（沉浸感来源）

- [ ] 日志自动滚动：战斗日志过多时，自动保持在最底部。
- [ ] 色彩系统：为气血、伤害、装备品质（绿蓝紫橙）设置不同的 CSS 颜色。
- [ ] 简易打字机效果：让文字一段段跳出，而不是瞬间出现。

## 建议的开发路线图 (Timeline)

| 周次   | 任务目标       | 成果                                              |
| ------ | -------------- | ------------------------------------------------- |
| Week 1 | 完善结算与养成 | 战斗赢了能升级，数值会变强，且数据能存住。        |
| Week 2 | 实现掉落与背包 | 打怪能掉灵石和木剑，能穿在身上。                  |
| Week 3 | 构建文字地图   | 可以在"新手村"、"后山"、"乱葬岗"之间来回走。      |
| Week 4 | 润色文案与细节 | 增加更多修仙描述，调整数值平衡，发布第一个 Demo。 |
